麻雀計番 UI 流程更新 — v1.4.2-ui

這是完整 app.js 替換檔，不是零散 patch。以使用者提供的 app_x5f_4_x5f_fixed.js 為基礎。
保留現有外部 CSS、原有注入樣式、配色與主題設定；新增介面沿用現有 class。
本套件不是獨立網站：必須配合原網站的 HTML、CSS、engine、worker、manifest、service worker 等檔案。

安裝
1. 先匯出網站內 JSON 備份，並備份原 app.js 與 version.json。
2. 用本套件 app.js 取代原檔。原有 HTML/CSS/engine/worker 不需要因本次改版而改名或替換。
3. 同步部署本套件 version.json；若原 version.json 有其他用途欄位，保留原檔並只更新 version 和 updated。
4. 若現有 service worker 固定快取舊 app.js，需按原部署方式更新快取版本或清除快取。
   本套件未包含你的 sw.js，不能保證只上傳 app.js 就會立即刷新已安裝 PWA。
5. 先在測試副本試開局、食炮、自摸、雙響、流局、撤銷及備份還原，再部署正式站。

新流程
選玩法 → 四位玩家名稱/emoji/座位/莊家 → 牌桌。
點玩家卡 → 自摸或食炮 → 食炮時選出銃者 → 原有牌型編輯頁 → 預覽 → 確認。
成功記錄後返回牌桌，顯示查看記錄/撤銷入口；失敗或取消不清空已輸入手牌。
雙/三響：加入一位後選另一位，沿用出銃者；可以直接確認已加入名單，空白當前手不計入。
即時籌碼/罰則保留在牌桌的可展開區，也保留在手牌編輯頁。

玩家設定
名稱必填且四人名稱不能相同；emoji 使用內建選單，不提供圖片上傳。
四位預設 emoji：🐉 🐯 🐼 🦊。不強制四人 emoji 不同。
玩家設定使用草稿；確認才保存，取消不會改動現有名稱、emoji 或分數。
有正在輸入的本局時，不允許修改玩家/座位/莊家/風圈/連莊。
舊備份無 emoji 時自動補預設；已有歷史紀錄的舊牌局可繼續使用，不強制重填。
重新開一場會顯示玩家設定並沿用上次名稱/emoji。
玩家資料隨現有 JSON 備份保存。

驗證與計分修正
共同放炮牌只計一次；未知食糊牌標示待確認。
所有人未指名時，以同一款候選共同牌檢查整體張數可行性。
自摸分開檢查實體張數，不要求指定共同放炮牌。
廣東牌確認使用 settleHK，不走台牌拉數流程；保留 bao/raw/qiang。
廣東牌扣槓後驗放炮牌的原有 analyzeHK 邏輯保留。
起糊番數檢查涵蓋最終所有食糊者，不能只結算 pending 避過。
普通/廣東牌的正式記錄必須通過牌型分析；不再默許分析失敗後以基本/手動番項入帳。
廣東牌低於起糊番數仍沿用原程式的詐糊罰分慣例，會先要求確認。

測試
Node 語法檢查通過；47 項自動回歸測試通過。
測試載入使用者提供的實際 engine.js、engine2.js、engine4.js、engine_hk.js，
執行完整 app.js（只在記憶體內加入測試存取接口；正式檔不含接口）。
DOM/localStorage 使用模擬，沒有網絡呼叫；未完成 Safari 真機或瀏覽器端視覺測試。
百搭背景 worker、所有番型及 service-worker 更新仍須在原網站環境驗證。
未確認的本局草稿僅保留於當前頁面執行期間；重新載入網頁不保證保留草稿。

測試指令（Node）：
node regression_tests.js app.js 原有engine所在資料夾
例如測試檔、app 與 engines 同一資料夾：
node regression_tests.js app.js .

不含變更：沒有重寫計番引擎，沒有帳號/房間/上傳頭像，沒有更換視覺主題。
