麻雀計番 1.4.2 — 完整主程式更新

版本號：1.4.2（沒有 v 前綴，沒有 -ui 後綴）。
以使用者提供的 app_x5f_4_x5f_fixed.js 為基礎，整合本次及先前已討論的更新。
app.js 是完整替換檔，不是 patch 片段；仍須配合原網站 HTML/CSS/engine/worker/manifest/service-worker 等檔案，不是獨立網站。

部署
1. 先匯出網站 JSON 備份並備份原 app.js、version.json。
2. 替換 app.js；同步替換 version.json。原版本檔若有其他用途欄位，可保留原檔而只修改 version 及 updated。
3. 原有 HTML、CSS、計番 engine、worker 不需要因本次更新而更改。
4. 按網站原部署方式更新 service-worker 快取；本套件沒有原 sw.js，沒有修改它。只換 app.js 不保證已安裝 PWA 立即載入新檔。
5. 檢查網站版本顯示為 1.4.2；先在測試副本驗證，再部署正式站。

牌桌
玩家卡大字只顯示總淨額：已收付淨額＋未收拉－未付拉。
不在卡內分開顯示未收/未付；牌桌下方的逐筆拉數、口數及結清按鈕保留。
廣東牌沒有台牌拉數，直接顯示已收付淨額。
原配色、主題及兩段注入式 CSS 保持原樣。

歷史頁
每筆大字顯示本筆淨變動，而非截至該局的累計總額：
本筆淨變動＝本筆已收付變動＋（本筆完成後拉數淨額－本筆開始前拉數淨額）。
例如已收付 +20、未結算淨變動 +30，大字為 +50，小字分別註明 +20 及 +30。
如果同時有未收拉及未付拉變動，另列兩方向的變動以免淨額遮住資訊。
只結清拉數時，現金增加、未結算減少，大字淨變動為 0；原結清事件明細仍在。
小字的「未結算變動」是當筆造成的變化，包含新增/結清/踢半等，不是目前累計的未結拉數。
食糊者、番型、出銃者、包牌及原有事件明細保留。

歷史快照及舊資料
新記錄保存 ledgerBefore、ledgerAfter、financeMode 等欄位；先完成 ledger 更新，再在儲存時封存 after 快照。
保留原 deltas 作為現金變動，不用總淨變動覆寫它，以免損壞實際收付帳。
之後結清或改動目前拉數，不會改寫有快照的舊紀錄結果。
舊紀錄無 ledgerAfter 時，優先用下一筆 ledgerBefore；最後一筆用目前 ledger 推算。
若缺少足夠快照，不會假設拉數為 0：歷史大字顯示 —，列出已收付並提示無法確認總淨變動。
以上快照欄位會隨原有 JSON 備份保存；查看歷史不會改寫舊紀錄。

保留的 UI/UX
四位玩家名稱、emoji、座位及莊家設定；沒有圖片上傳。
點名稱欄即清空；沒有輸入/只有空格/刪光則還原點入前名稱；直接確認而未失焦亦會處理。
點玩家卡選贏家 → 自摸/食炮 → 食炮時選出銃者 → 原牌型輸入頁 → 預覽/確認 → 返回牌桌。
失敗或取消不清空手牌；返回牌桌可繼續本局。雙/三響沿用出銃者，一次結算。
即時籌碼/罰則保留；玩家 emoji 隨備份保存。
未確認的手牌草稿只保留於本次頁面執行期間，重新載入不保證保留。

保留的計分修正
共同放炮牌只計一次；未指名為待確認；無鎖定時以單一候選共同牌驗證整體張數。
自摸分開驗實體牌數，不要求共同放炮牌；百搭不能作放炮牌。
廣東牌使用 settleHK 入帳，不走台牌拉數。原扣槓後驗放炮牌邏輯保留。
普通/廣東牌正式記錄須通過牌型分析，不再自動退回基本番項記錄無效牌型。
起糊番數驗證涵蓋最終所有食糊者，包括只確認 pending 的情況。
廣東牌不足起糊番數仍沿用原程式的詐糊罰分慣例並先要求確認。
